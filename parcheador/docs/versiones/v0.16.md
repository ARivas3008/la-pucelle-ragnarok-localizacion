# v0.16 — Integración experimental de scripts y anclas CP932

**Estado: CANDIDATO EXPERIMENTAL.** No es una versión 100 % traducida ni comprobada en PPSSPP.

## Alcance técnico
- Mantiene la GUI Windows y el parcheador v0.13 para la ISO PSP y los cuatro `DL_JP_00.EDAT` a `DL_JP_03.EDAT`, en una primera fase.
- Permite ejecutar después el reubicador v0.14 en modo conservador, sobre **copias** preliminares de la ISO y DLC.
- Añade el modo optativo `fase` de v0.16, que ensaya conservar la fase interna CP932 (segundo byte a segundo byte). Rechaza candidatos ausentes o separados más de dos caracteres.
- Mantiene el modo antiguo `experimental` v0.12 por compatibilidad de investigación, no lo expone como opción por defecto del EXE.
- Reporta cada unidad y continúa preservando `Now Loading`.
- Genera el EXE Windows con CI; el artefacto **no contiene** ISO, EDAT ni LZS comerciales.

## Evidencia de los originales de 15-11-2026
Sobre los binarios aportados por el titular se reprodujeron 14 unidades con 15 anclas internas CP932; la unidad 1759 contiene dos. El `START_JP.LZS` adjunto coincidió byte a byte con el que reside en la ISO (SHA-256 `22be383708fe5520cf9da7efa302a2502a9fca82727874b644ab64ad2d72620a`).

Al ensayar los textos propuestos desde `v0.15/casos_14.csv` con la misma asignación gaiji de `fuentes_es.py`, solo **cuatro unidades** presentaron una propuesta de segundo byte dentro de la tolerancia: **1758, 1759, 3924, 4170**. Las otras diez carecían de candidato de la misma fase o excedían la tolerancia. **Cuatro candidatos no son cuatro validaciones**: la semántica del bytecode sigue desconocida.

## Cómo usar el EXE

1. Descargar el artefacto de Windows desde la ejecución de GitHub Actions `v0.16 Windows EXE experimental`.
2. Extraer en el equipo del usuario la ISO y el directorio `ULJS00244` con los cuatro `DL_JP_*.EDAT`.
3. Elegir ISO, DLC y carpeta de salida en la GUI; los archivos de origen jamás se sobrescriben.
4. Activar opcionalmente la casilla de scripts conservadores. Sin ella, el comportamiento es el del parcheador v0.13.
5. La casilla de 14 referencias únicamente habilita el **ensayo** de fase. Exige confirmación explícita; puede dejar unidades bloqueadas y nunca es apta para release sin pruebas.
6. Revisar `resumen.json`, `reporte_por_unidad.csv` y, si corresponde, `v016_scripts_fase/resumen_script_v014.json`.

La GUI procesa primero la salida preliminar v0.13 y luego entrega una copia independiente del trabajo v0.14/v0.16. Si falla la reubicación o la validación de datos, aborta con error; no sobrescribe los originales.

## Pruebas y aceptación
```bash
python -m unittest discover -s parcheador/app/tests -v
python -m unittest discover -s parcheador/investigacion/v0.14/tests -v
python -m unittest discover -s parcheador/investigacion/v0.16/tests -v
```

La ejecución de tests sintéticos, el cifrado de hashes y la reversión binaria **no prueban** que la ISO se ejecute o que todas las escenas sean visibles y estén sincronizadas.

Para declarar el 100 % se requieren: resolución documentada de las diez unidades sin equivalencia de fase, identificación por trazas PPSSPP de los 15 índices, estados de aceptación por cada una de las 26 258 unidades, fusión editorial del resto de corpus y QA visual para juego y los cuatro DLC. No incluir ni distribuir material comercial en el repositorio.
