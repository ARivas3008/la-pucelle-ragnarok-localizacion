# Metodología v1.1 — Pipeline MTL contextual reproducible

## Punto de partida
La metodología v1.0 ya contiene diez fases, reparto por grupos, pruebas de límites en **bytes** y un checklist. v1.1 agrega el **puente práctico** entre la división de corpus y los sistemas MTL/LLM externos sin introducir textos comerciales ni acoplarse a un proveedor.

## Flujo mínimo
```text
copias legítimas de juego/DLC → adaptador de extracción por formato
  → unidades_extraidas.csv (unit_id, grupo_id, recurso, original, contexto)
  → planificar_corpus.py (lotes contextuales de 40–60 grupos)
  → preparar_mtl_contextual.py --solicitudes (JSONL por grupo)
  → servicio MTL o revisión asistida que conserva unit_ids
  → preparar_mtl_contextual.py --respuestas (borradores MTL validados)
  → revisión humana por escena + glosario + hashes/tokens
  → verificar_presupuesto.py (bytes REALES, CP932/gaiji, NUL, límites)
  → parcheador específico del juego (offsets, punteros, fuentes)
  → PPSSPP/equivalente (pruebas de escena y captura)
  → acta de QA + archivo de parches diferenciales
```

## Ejecución genérica (Python 3.10+, sin APIs)

```bash
# Entrada: CSV exportado por un adaptador de formatos, NO datos adivinados
python metodologia/scripts/planificar_corpus.py --unidades unidades_extraidas.csv --salida lotes --grupos-por-lote 50

# Agrupa por lote/escena/grupo y añade contexto; NO llama a un proveedor de MTL
python metodologia/scripts/preparar_mtl_contextual.py --lotes lotes --solicitudes solicitudes_mtl.jsonl

# El proveedor externo o traductor debe producir respuestas_mtl.jsonl:
# {"unit_id":"101","mtl_es":"¡Hola, {0}!"}
# {"unit_id":"102","mtl_es":"Buenos días."}
python metodologia/scripts/preparar_mtl_contextual.py --lotes lotes --respuestas respuestas_mtl.jsonl --salida-borradores borradores_mtl.csv

# DESPUÉS de la revisión contextual: generar revisiones_por_unidad.csv con
# es_revisado y estado=revisado según protocolo y aprobar manualmente.
python metodologia/scripts/verificar_presupuesto.py --unidades unidades_extraidas.csv --revisiones revisiones_por_unidad.csv --gaiji-json mapeo_fuentes.json --salida presupuesto.csv

python -m unittest discover -s metodologia/tests -v
```

**Restricciones:** este pipeline no divide una intervención en cualquier punto ni convierte una MTL en revisión aprobada. El estado `BORRADOR_PENDIENTE_REVISION` **no** debe trasladarse automáticamente a `revision.csv`. Las entradas con variables distintas reciben `MTL_MARCADORES_ALTERADOS`; las ausentes quedan `SIN_BORRADOR`.

## Cómo distribuir el trabajo para perder el menor tiempo

- **Una sola vez (antes del equipo):** versiones/hashes, adaptadores de solo lectura con ida/vuelta, inventario, IDs estables, glosario inicial y CI.
- **En paralelo:** primer equipo implementa parser/packer para todas las familias; los revisores trabajan microtandas distintas; un equipo QA prepara escenarios y capturas del original.
- **Por cada tanda:** exportar JSONL con contexto; obtener MTL como propuesta; revisor contrasta JP/EN; aprobar terminología; medir bytes; smoke build en copia; registrar bloqueos por formato.
- **Centralizado:** cambio de IDs, offsets maestros, términos globales, inserción binaria, publicación y etiquetado de 100 %.
- **Bucle corto:** atender primero menús, prólogo, guardado, HUD y textos con variables; mantener los casos de puntero desconocido aislados para que no bloqueen las demás traducciones.

## Presupuestos según el destino
- Campo fijo N bytes: `bytes(codificado) + bytes(NUL) <= N`; también respetar ancho en píxeles.
- Script opcode con u8: máximo **255 bytes incluyendo terminador**; una referencia a otro byte del script requiere mapa/reubicación.
- Diálogo variable: presupuesto depende de intervención completa y bytecode, no cortar por número de caracteres.
- Texturas/atlas: se debe reservar espacio gráfico, UV y paleta; no hay «bits de texto» universales.
- Binario ejecutable: el coste puede ser un offset fijo/puntero, no solo tamaño del texto.
- Vídeo y subtítulos: identificar si la cadena es texto, capa gráfica o vídeo antes de elegir un adaptador.

## Entregable de cada versión del juego
`SHA original` + `SHA nuevo`, informe por `unit_id` y `grupo_id`, scripts reproducibles, cambios binarios limitados al recurso, validación inversa y acta visual. No mezclar contadores de universos superpuestos.

**Esta rama es independiente de las revisiones editoriales y del parcheador v0.16.1.** Debe incorporarse por PR propio para conservar el método genérico.
